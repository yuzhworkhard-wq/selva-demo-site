# 资源库产品包与视频生成联动 · UX 交互说明书

---

## 1. 功能定位与设计背景

### 1.1 业务背景与痛点
在出海短视频广告与投放素材生产中（涵盖网赚、短剧、轻量游戏、跨境电商等垂直行业），视频画面中往往需要高度真实的**「产品身份元素」**与**「本地化金融合规元素」**，典型包括：
1. **产品品牌标识**：应用图标（App Logo）、名称、核心卖点。
2. **应用原生界面**：登录页、主界面、提现进度条、中奖弹窗等高清竖屏界面截图（App UI）。
3. **当地主流银行 / 支付渠道**：如巴西的 Pix、印尼的 Dana、菲律宾的 GCash、韩国的 KakaoPay 等。在提现或充值镜头中，使用错误或劣质的支付 Logo 会导致受众信任度瞬间崩塌，极大拉低转化率。
4. **当地法定流通纸钞**：如印尼盾（IDR）、雷亚尔（BRL）、日元（JPY）等现行大额钞票，用于收益展示、数钱或到账特写镜头。

**历史操作痛点**：
- **重复搬运成本高**：剪辑/制作人员每次针对同一个 App 生成变体视频时，都要反复翻找本地文件夹，逐一上传 3~5 张截图与图标。
- **本地化元素容易出错**：非母语国家投放团队经常混淆东南亚或拉美各国的支付通道（如将墨西哥的 OXXO 错配给智利，或将美元误配在非美区）；AI 生成货币时极易产生“虚假货币”或乱码纹理。
- **图文割裂，AI 无法自如调用**：用户手动上传了参考图，但生视频模型与提示词不知道哪张是“应用主图”、哪张是“到账支付 Logo”，导致成片无法准确交代画面逻辑。

### 1.2 解决方案：标准化「产品包」体系
平台构建了**「资源库产品包（Product Pack）」**与**「视频生成工作台（Video Gen Composer）」**的深度协同机制：
- **资源库沉淀**：通过 Google Play 应用链接一键自动解析，结构化聚合「Logo + 应用画面 + 当地首选银行/支付 Logo + 当地纸钞」，形成可复用的产品数字资产包。
- **一键挂载**：在视频生成工具内，输入框左上角常驻轻量挂载胶囊，用户无需逐张传图，一键挂载整个产品包。
- **Magic Prompt 智能感知与调度**：产品包挂载后，Magic Prompt 扩写引擎自动获取包内所有关联图片，在生成分镜提示词时智能插入 `@图片N` 引用；同时，后端执行**「先查预置图片，查不到再调 AI 生成」**的可靠降级策略，确保当地银行与纸钞绝对合规、高清。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 资源库 (Asset Library)                                                       │
│ 粘贴 Google Play 链接 ➔ 自动提取应用资产 + 匹配当地金融资产 ➔ 沉淀标准化「产品包」 │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       ▼ 挂载 / 用它生成视频
┌─────────────────────────────────────────────────────────────────────────────┐
│ 视频生成工作台 (Video Gen)                                                    │
│ ┌─────────────────────────────────────────────────────────────────────────┐ │
│ │ [📦 产品包 · CashDrama ✕] (挂载胶囊)                                    │ │
│ │ 描述你想生成的视频，输入 @ 引用参考素材…                                │ │
│ ├─────────────────────────────────────────────────────────────────────────┤ │
│ │ 提示：已挂产品包，打开 Magic Prompt 后将自动调用包内图片                │ │
│ │ [Magic Prompt: 自动/开 ▾] ─── 触发后台分镜扩写并引用包内图片 ➔ 提交生成 │ │

#### 2. 产品包卡片信息结构与交互
每张产品包卡片包含以下信息维度与交互热区：
- **头部身份区**：
  - 应用 Logo 缩略图（若未抓取成功则显示首字母大写徽标）。
  - 应用主名称（超出单行省略并带原生 title 提示）。
  - 标签组：投放国家/地区名称、当地主流支付方式（前置支付方式官方 Logo）。
- **截图预览区**：固定 3 联格展示应用核心画面（9:16 竖屏缩略），不足 3 张时保留虚线浅灰空槽，保持卡片高度统一。
- **底部状态区**：展示总素材项数（Logo + 截图 + 支付 + 纸钞）与画面张数；右侧配有更多操作浮标 `[···]`。

  - **点击卡片主体**：呼出全量产品包预览弹窗（Modal Wide），可全尺寸检视画面、银行 Logo、纸钞与包名原链。
  - **点击更多菜单 `[···]`**：
    - `查看详情`：打开产品包详情预览。
    - `用它生成视频`（核心直达路径）：自动打开「视频生成」工作台，并将当前产品包无缝挂载就位。
    - `删除`：二次确认气泡，仅允许创建者或管理员执行删除。

### 2.2 创建产品包 · 向导流程与资产解析

点击「创建产品包」触发模态弹窗，系统采用「两步轻量流（Input ➔ Confirm）」设计：

```
[第 1 步：输入应用与地区] ───────────────➔ [第 2 步：资产确认与重新生成]
- Google Play 链接输入                     - 自动填充 Logo、应用截图 (≤3张)
- 目标国家/地区选择 (分组多国选择器)         - 自动匹配当地银行支付 Logo
- 智能识别应用名称与默认市场               - 自动匹配当地流通纸钞
                                           - 提供银行/纸钞自定义重成与上传替换
```

#### 步骤一：输入应用与目标市场
1. **Google Play 链接输入框**：
   - 必填，支持粘贴如 `https://play.google.com/store/apps/details?id=com.xj.cash.drama` 格式链接。
   - 包含快捷粘贴或 Demo 预填示例按钮。
2. **目标投放国家 / 地区选择器（Region Picker）**：
   - 弹窗内置地区分组下拉选择面板，涵盖 29 个主流出海国家/地区。
   - 支持按中文名、英文代码或拼音实时检索（如输入“巴西”或“BRL”快速定位）。
   - **智能预设规则**：若链接为已知受托包名，系统自动将推荐地区锁定至最佳目标市场（如 CashDrama 默认锁定巴西）；用户仍可手动更改。
3. **主操作**：点击「下一步：自动识别素材」，进入抓取过渡态（Fetching Skeleton，通常在 800ms 内完成）。

#### 步骤二：资产确认与兜底微调（Confirm Draft）
系统自动完成应用元数据抓取与本地化金融素材关联，展示可编辑确认画板：

- **应用画面卡槽**：
  - 允许单个移除并追加上传本地图片；
  - 严格限制 1~3 张，卡槽角标显示顺序编号（#1、#2、#3）；
  - **重要调用规则（首位应用图默认调用）**：虽然产品包支持保存 1~3 张应用画面，但**视频生成调用时默认仅调用排在第 1 位的那 1 张（主核心界面截图）**，第 2、第 3 张作为产品包内的备选/储备资产。用户在创建与确认素材时，应将最希望在成片中展示的核心界面（如主游戏界面、提现结算页）排在首位。

  - **产品 Logo**：支持点「上传替换」。

- **自定义微调重成（重要入口）**：
  - 若用户投放更细分的二级银行或电子钱包（例如巴西不走中央银行 Pix，而想强调具体开户行 `Nubank`），可在输入框键入名称并点「重新生成」。

  - 同理，支持输入币种名称重新检索/生成特定面额的法定纸钞。
- **提交与同步**：
  - 点击「确认创建」，系统将产品包存入库中，并通过跨组件/跨 iframe 通信协议（`pushProductPacksToCloneTool`）将最新包列表同步至底层视频生成工具，无需重新加载页面。

## 3. 视频生成与产品包的联动机制

### 3.1 挂载入口与挂载胶囊（Pack Pill）
在视频生成工作台（Video Gen Composer）中，产品包被定义为**「批次生产的前置产品声明」**，统领整批视频的受众地区、素材口径与合规要素，而非输入框内的零散附件。

#### 1. 胶囊位置与视觉层级
产品包挂载胶囊常驻于输入主卡片（Composer）的**左上方独立状态行（Pack-Pill Row）**：
- 它位于通用多模态参考素材停靠区（Idea Dock）之上，明确视觉从属关系；
- 避免与普通的参考图/参考视频 chip 混杂在一起。

```
                    ┌────────────────────────────┐
                    │ [📦 CashDrama          ✕ ] │  ← 挂载胶囊 (已挂态)

│ │ (可选) 手动上传的参考图/首帧图 chip 停靠区 (Idea Dock)                    │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│ 描述你想生成的视频，输入 @ 引用参考素材…                                     │
│                                                                              │
│                                                                     128/1000 │
├──────────────────────────────────────────────────────────────────────────────┤
│ ⚠️ 已挂产品包，但 Magic Prompt 关闭时不会自动调用包内图片 (仅在 Magic=关时提示)│

#### 2. 胶囊状态机

| 状态 | UI 表现 | 用户交互行为 |
| :--- | :--- | :--- |

### 3.2 产品包与 Magic Prompt 的自动调用逻辑（核心规范）

视频生成底栏提供 **Magic Prompt（智能提示词扩写）** 开关，提供 `自动 (auto)`、`开 (on)`、`关 (off)` 三种模式。产品包的素材调用与 Magic Prompt 深度绑定。

#### 1. 开启 Magic Prompt 时的自动注入（Auto Ingestion）
- **触发机制与素材筛选（应用图默认只调第 1 张）**：
  - 当挂载了产品包且 Magic Prompt 设置为 `auto` 或 `on` 时，用户点击「生成」按钮，系统**自动提取产品包内的关键图片**。
  - **重要约束：应用截图默认只调用排在第 1 位的那 1 张**：
    产品包虽然支持维护 1~3 张应用截图（`appImages`），但短视频通常具有极高的节奏与单一视觉聚焦诉求，若一次性灌入多张复杂 UI 容易导致模型焦点发散或分镜提示词打架。因此，**系统默认只调用排在第 1 位的应用截图（Shot #1 核心主界面）**，第 2、第 3 张留在产品包内作为备选资产暂不注入默认扩写流：
    $$\text{PackImages}_{\text{default}} = \{\text{Logo}\} \cup \{\text{AppImage}_{\text{\#1 (首位主图)}}\} \cup \{\text{PaymentLogo}\} \cup \{\text{NoteImage}\}$$
- **合并素材池**：系统将产品包素材并入当前任务的扩写图片池：
  $$\text{EffectiveImages} = \text{UserAttachedImages} + \text{PackImages}_{\text{default}}$$
- **分镜推导与自动打标**：
  Magic Prompt 扩写引擎在分析用户简短提示词（如：“*巴西女孩在公交车上看剧赚钱，提现到账开心特写*”）时，能感知到产品包的语义上下文，自动在生成的多条分镜脚本中精准引用包内图片序号（如 `@图片1: 产品Logo`、`@图片2: 应用核心界面(#1)`、`@图片3: Pix支付Logo`、`@图片4: 100雷亚尔钞票`）。
- **成片效果保证**：
  视频模型依托多模态视觉注入机制，在对应的关键帧处准确呈现产品原版 UI、真实 Pix 标志与无瑕疵的巴西雷亚尔现钞，彻底避免 AI 幻想生成的乱码界面。

#### 2. 关闭 Magic Prompt 时的警告与降级表现（Strict Warning & Fallback）
- **设计初衷**：若 Magic Prompt 被设为 `off`（关闭），系统将完全遵从用户原始填写的字面提示词，不会启动后台 LLM 进行素材语义编排与分镜改写。
- **显式警告拦截（Composer Warn）**：
  一旦检测到 `mountedPack !== null && magic === 'off'`，底栏正上方立即唤起警告条：
  ```
  ⚠️ 已挂产品包，但 Magic Prompt 关闭时不会自动调用包内图片
  ```
- **数据流降级**：
  在 `magic === 'off'` 状态下强行提交任务时：
  1. 系统**不会**将产品包图片注入多模态模型的第一阶段生成流中（因为未经 Magic 语义编排的模型无法理解为何突然多了 6 张异构图片）；
  2. 产品包元数据仍会作为上下文归档至任务记录（Task Payload），供后续任务看板查看。

#### 3. 模型首帧与配额判定兼容
- **非手动超限豁免**：常规视频模型对手动添加的参考图有数量上限限制（如最多 1 张或 3 张）。产品包素材是由 Magic Prompt 后台智能调度的系统级资产，**不计入用户手动参考图的「超出上限描红拦截」**，保障操作流畅度。
- **首帧满足兜底**：若当前模型属于「必须上传首帧图才能生成」（`imageRequired === true`）的类型，挂载了产品包后，系统认可产品包提供的应用画面作为有效图像输入，解除生成按钮的置灰阻断。

## 4. 当地银行 Logo 与纸钞图片的检索与生成策略

### 4.1 双层资产服务架构（Preset-First, AI-Fallback）
在产品包创建、编辑以及更换国家时，针对「当地银行/支付方式 Logo」和「当地流通纸钞图片」，系统统一遵循**「后端优先查询预置高清资产库，未命中再调用 AI 动态生成」**的架构规范：

```
                用户输入/选择国家或指定银行/纸钞名称
                                 │
                                 ▼
               ┌──────────────────────────────────┐
               │    后端首选资产路由控制器        │
               └─────────────────┬────────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
       [银行/支付方式检索]               [当地纸钞素材检索]
                 │                               │
        查 PAYMENT_LOGOS 预置库          查 REGION_CURRENCY 预置库
                 │                               │
        ┌────────┴────────┐             ┌────────┴────────┐
        ▼                 ▼             ▼                 ▼
     [命中]            [未命中]       [命中]            [未命中]
        │                 │             │                 │
  返回官方标准       调用 AI 生图/    返回官方真实     调用 AI 货币防伪
  SVG/PNG 资产       矢量排版引擎     高清纸钞扫描图    纹理生成模型
        │                 │             │                 │
        └────────┬────────┘             └────────┬────────┘
                 │                               │
                 └───────────────┬───────────────┘
                                 │
                                 ▼
                     回填产品包卡槽并支持用户预览
                     (支持重新输入生成与本地上传替换)
```

### 4.2 检索与生成执行细则

#### 1. 第一层：预置图片库精确匹配（Local Preset Cache）
- **银行 / 支付方式 Logo**：
  - 后端收录目标市场**官方透明背景矢量 SVG 或高精度 PNG**，统一命名归档至 `public/product-packs/payments/`；
  - 检索逻辑执行大小写不敏感与别名映射匹配（例如输入 `Touch 'n Go`、`touch n go` 或 `tng` 均能精准命中同一官方预置文件）。
- **当地法定流通纸钞**：
  - 后端依据 ISO 货币代码收录目标市场**流通面额最高频的高清钞票正面扫描图**，归档至 `public/product-packs/notes/<code>.jpg`；
  - 检索逻辑执行国家代码、币种中文名、ISO 代码多向倒排索引（例如输入 `BRL`、`巴西` 或 `雷亚尔` 均能精准命中 `product-packs/notes/brl.jpg`）。

#### 2. 第二层：AI 动态生成（AI Fallback Generation）
当用户指定非预置的小众商业银行、区域性信贷产品，或冷门国家货币时，系统平滑降级至 AI 动态生成链路：
- **银行 / 支付 Logo 动态生成**：
  - 提取银行品牌名称，结合金融机构通用配色算法（基于字符串哈希与金融蓝、绿、红、紫主调），调用生成模型输出标准品牌徽标或矢量 Icon；
  - 规范比例为 1:1，自动做安全边距留白与圆角处理，生成结果立即缓存。
- **当地纸钞动态生成**：
  - 依据输入的币种全称或国家名称，调用 AI 货币仿真生成微服务；
  - 自动渲染包含货币防伪底纹、面额数字水印、官方花边装饰的 320×150 比例横版货币票样；
  - 生成过程界面呈现「生成中…」微动效，生成后弹出 Toast 提示用户已更新。
- **人工纠错闭环**：
  无论预置还是 AI 生成的图片，每个卡槽均提供独立的「上传替换」通道，确保极端定制需求下 100% 可行。

## 6. 任务中心回溯与异常场景处理

### 6.1 任务中心（Task Detail）回溯机制
当包含产品包的视频任务提交后：
1. **输入参数持久化**：任务元数据持久化记录 `productPack` 对象（含 id、名称、地区、Logo、截图池、支付名称与 Logo、纸钞信息）。
2. **任务详情页展示**：
   - 任务参数概览区渲染「产品包 Chip」标签：`[ 📦 CashDrama · 巴西 · Pix ]`；
   - 点击该 Chip 可展开完整资产抽屉，查看生成本批视频时引用的 6 项确切原图，方便团队后期复盘与合规复核。
3. **重新编辑复用**：从任务详情页点击「基于此任务再生成」时，系统自动反向挂载原任务的产品包与提示词，用户无需重新绑定。

### 6.2 异常与边界场景交互矩阵

| 场景分类 | 触发条件 | 系统表现与 UX 反馈 | 容错处理与操作出口 |
| :--- | :--- | :--- | :--- |
| **链接解析异常** | 用户输入的 Play 链接格式无效或该 App 已下架 | 输入框失焦时报红提示：`无法识别该应用，请检查链接或手动创建` | 允许用户跳过自动抓取，进入空白确认表单完全手动上传。 |
| **挂载后关 Magic** | 用户已挂载产品包，但将 Magic Prompt 切换为 `关` | 底栏上方常驻黄色提示条：<br>`⚠️ 已挂产品包，但 Magic Prompt 关闭时不会自动调用包内图片` | 用户可点击开启 Magic，或知情确认直接纯文本生成。 |
| **产品包被删除** | 任务草稿引用的产品包被原创建者在资源库中删除 | 视频生成挂载胶囊显示置灰态并标注：`[ 产品包已失效 ✕ ]` | 点击 `✕` 卸载，提示「请重新选择其他产品包」。 |
| **冷门银行生成超时** | 用户自定义输入的银行名称触发 AI 动态生图时网络波动 | 超过 5 秒未返回时停止 Loading，卡槽显示「生成未完成」 | 提供「重试」按钮与「上传本地图片」兜底，不阻塞产品包保存。 |
| **多模型切换约束** | 挂载产品包后，用户将视频模型切换为仅支持纯文本的极简模型 | 底部警告条提示：`当前模型不支持多模态参考图，产品包图片将在生成时忽略` | 阻断提示明确，避免用户对成片产生非预期抱怨。 |

## 7. 总结与设计价值
通过将「产品包」作为独立且高内聚的资产载体，并在「视频生成」中通过胶囊挂载与 Magic Prompt 建立自动化调用管道，本设计达成了以下核心价值：
1. **降低制作门槛**：一次创建产品包，全团队终身复用；无需制作人员死记硬背各国复杂的本地银行与货币名称。
2. **保证合规真实**：依托「先查预置、查不到 AI 生成」的双层架构，确保出海高敏感度金融镜头 100% 真实、高清、专业。
3. **驱动 AI 协同**：通过 Magic Prompt 语义自动注入，真正打通了「产品资产库 ➔ 提示词工程 ➔ 多模态生视频」的端到端自动化出片链路。
